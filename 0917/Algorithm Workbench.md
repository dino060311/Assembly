### 1. Define four symbolic constants that represent integer 25 in decimal, binary, octal, and hexadecimal formats.

정수 25를 10진수, 2진수, 8진수, 16진수 형식으로 나타내는 심볼릭 상수 4개를 정의하시오.

**답:**

```asm
DEC_25 = 25          ; 10진수
BIN_25 = 11001b      ; 2진수 (b 접미사)
OCT_25 = 31q         ; 8진수 (q 또는 o 접미사)
HEX_25 = 19h         ; 16진수 (h 접미사)
```

네 상수 모두 어셈블 후 동일한 값 25를 가진다.

### 2. Find out, by trial and error, if a program can have multiple code and data segments.

시행착오를 통해, 하나의 프로그램이 여러 개의 코드 세그먼트와 데이터 세그먼트를 가질 수 있는지 알아보시오.

**답:** **가능하다.**

```asm
.data
val1 DWORD 10

.code
main PROC
    mov eax, val1

.data
val2 DWORD 20

.code
    add eax, val2
    ret
main ENDP
```

`.data`와 `.code` 지시어를 여러 번 반복해도 어셈블 오류가 발생하지 않는다. 어셈블러는 같은 이름의 세그먼트에 속한 내용을 모두 이어 붙여(concatenate) 하나의 데이터 세그먼트와 하나의 코드 세그먼트로 합친다.

### 3. Create a data definition for a doubleword that stored it in memory in big endian format.

더블워드를 메모리에 빅 엔디안 형식으로 저장하는 데이터 정의를 작성하시오.

**답:**

```asm
bigEndian BYTE 12h, 34h, 56h, 78h    ; 12345678h 를 빅 엔디안으로 저장
```

`DWORD 12345678h`로 선언하면 x86은 자동으로 리틀 엔디안(78 56 34 12)으로 저장한다. 따라서 빅 엔디안으로 저장하려면 `BYTE` 지시어를 사용해 상위 바이트부터 직접 나열해야 한다.

| 메모리 주소 | 값 |
|---|---|
| 0 (낮은 주소) | `12h` |
| 1 | `34h` |
| 2 | `56h` |
| 3 (높은 주소) | `78h` |

### 4. Find out if you can declare a variable of type DWORD and assign it a negative value. What does this tell you about the assembler's type checking?

DWORD 타입 변수를 선언하고 음수 값을 대입할 수 있는지 알아보시오. 이것은 어셈블러의 타입 검사에 대해 무엇을 말해주는가?

**답:** **가능하다. 오류 없이 어셈블된다.**

```asm
val1 DWORD -100        ; 오류 없음 → FFFFFF9Ch 로 저장됨
```

이는 어셈블러의 타입 검사가 매우 느슨하다(weak type checking)는 것을 보여준다. `DWORD`와 `SDWORD`는 어셈블러에게 **크기(4바이트)만 알려주는 역할**을 하고, 부호 유무는 구분하지 않는다. 값을 부호 있는 수로 해석할지 부호 없는 수로 해석할지는 프로그래머가 어떤 명령어를 쓰는지에 따라 결정된다.

### 5. Write a program that contains two instructions: (1) add the number 5 to the EAX register, and (2) add 5 to the EDX register. Generate a listing file and examine the machine code generated by the assembler. What differences, if any, did you find between the two instructions?

두 개의 명령어를 포함하는 프로그램을 작성하시오. (1) EAX 레지스터에 5를 더하고, (2) EDX 레지스터에 5를 더한다. 리스팅 파일을 생성해 어셈블러가 만든 기계어 코드를 확인하시오. 두 명령어 사이에 어떤 차이가 있는가?

**답:**

```asm
.386
.model flat, stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.code
main PROC
    add eax, 5
    add edx, 5
    INVOKE ExitProcess, 0
main ENDP
END main
```

리스팅 파일(`/Fl` 옵션)에서 확인한 기계어 코드:

| 명령어 | 기계어 코드 |
|---|---|
| `add eax, 5` | `83 C0 05` |
| `add edx, 5` | `83 C2 05` |

두 명령어 모두 3바이트이며, opcode(`83`)와 즉시값(`05`)은 같다. 차이는 가운데 **ModR/M 바이트 하나뿐**이다(`C0` ↔ `C2`). 이 바이트가 목적지 레지스터를 지정하며, EAX는 0번, EDX는 2번 레지스터이므로 값이 달라진다. 즉 레지스터 이름은 별도의 opcode가 아니라 ModR/M 바이트 안의 번호로 구분된다.

### 6. Given the number 456789ABh, list out its byte values in little-endian order.

456789ABh 라는 숫자의 바이트 값을 리틀 엔디안 순서로 나열하시오.

**답:** `AB 89 67 45`

| 메모리 주소 | 값 |
|---|---|
| 0 (낮은 주소) | `ABh` |
| 1 | `89h` |
| 2 | `67h` |
| 3 (높은 주소) | `45h` |

리틀 엔디안은 최하위 바이트(LSB)를 가장 낮은 주소에 저장한다.

### 9. Declare a 32-bit signed integer variable and initialize it with the smallest possible negative decimal value.

### 15. Show the order of individual bytes in memory (lowest to highest) for the following doubleword variable: val1 DWORD 87654321h

다음 더블워드 변수에 대해 메모리상의 개별 바이트 순서를 (낮은 주소에서 높은 주소로) 보이시오: `val1 DWORD 87654321h`

**답:** `21 43 65 87`

| 메모리 주소 | 값 |
|---|---|
| 0 (낮은 주소) | `21h` |
| 1 | `43h` |
| 2 | `65h` |
| 3 (높은 주소) | `87h` |

x86 프로세서는 리틀 엔디안 방식을 사용하므로 최하위 바이트 `21h`가 가장 낮은 주소에 저장된다.
